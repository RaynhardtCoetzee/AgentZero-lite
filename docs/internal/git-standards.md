# 🍏 Git & Deployment Discipline

## 1. Commit Message Format
[cite_start]Every commit must follow the `type: description` format[cite: 694, 695]:
- [cite_start]`feat`: New capability (e.g., `feat: AI SDK 6 ToolLoopAgent`) [cite: 697]
- [cite_start]`fix`: Bug fix (e.g., `fix: webhook credit retry logic`) [cite: 697]
- [cite_start]`docs`: Documentation updates [cite: 697]
- [cite_start]`perf`: Performance (e.g., `perf: 40% reduction in DB queries via 'use cache'`) [cite: 697]
- [cite_start]`refactor`: Structural change, no behavior change [cite: 697]
- [cite_start]`test`: Manual test results [cite: 697]

## 2. Branching Strategy
- **main**: Production-ready. Never commit directly. [cite_start]Merge from `dev` only[cite: 700].
- **dev**: Active working branch. [cite_start]All features happen here[cite: 700].
- **lite**: Generated by the stripping script. [cite_start]Never manually edited[cite: 700].

## 3. Versioning
[cite_start]Use Semantic Versioning (MAJOR.MINOR.PATCH) and update the `CHANGELOG.md` before every push to buyers[cite: 806, 810].
